# KGS — Kolkata Glazing Services — Website Context

This document is a complete reference of the codebase, content model, and design system for the KGS marketing website. It exists so that future prompts to an AI assistant can be short and unambiguous — paste relevant sections (or the whole file) as context when asking for "final touches," copy edits, layout tweaks, or new features.

---

## 1. What this site is

A premium, single-brand marketing website for **Kolkata Glazing Services (KGS)** — an architectural façade engineering company in India that designs, engineers, fabricates and installs structural glazing, curtain walls, ACP cladding, skylights, spider glazing and premium window systems.

The tone is **enterprise/industrial premium** — closer to a Linear/Notion SaaS aesthetic than a typical construction company site: lots of whitespace, restrained motion, a single accent blue, mono "eyebrow" labels, large display type, and glassy/blurred surfaces.

Public-facing pages: Home, Projects, Process, Expertise, Clients (+ client detail), About. There is also a password-protected `/admin` CMS for editing nearly all copy/images/data without touching code.

## 6. Content model — this is the most important section

**Nothing on this site is hardcoded as "the only source of truth" — every section is backed by a Supabase table, editable from `/admin`, with a sensible fallback baked into the component.** When asking for copy/content changes, decide whether the change should go into the **CMS schema/DB content** (so non-engineers can edit it later) or is a **one-off code/JSX fallback tweak**.

### How it works
- `src/lib/cms-schemas.ts` — the single registry of every editable "section": its DB table, whether it's a **singleton** (one row, e.g. Hero) or a **list** (many rows, e.g. Projects), and the exact fields with types (`text`, `textarea`, `number`, `image`, `url`, `select`, `boolean`).
- `src/lib/cms.ts` — generic React Query hooks: `useSingleton(table)`, `useList(table)`, `useUpdateSingleton`, `useUpsertListItem`, `useDeleteListItem`. Components call these directly, e.g. `useSingleton("hero")`.
- `src/lib/asset-map.ts` — resolves image URLs: passes through `http(s)://`/`data:` URLs untouched, resolves legacy `/src/assets/...` strings to Vite-bundled imports.
- The admin UI (`/admin/:section`) is **fully generic** — it reads `SCHEMAS[section]` and renders the right form automatically. Adding a new editable field is a one-line schema change, no new admin UI code needed.

### Singleton sections (one row each)
`hero`, `features_intro`, `statement`, `expertise_intro`, `projects_intro`, `process_intro`, `manufacturing`, `materials_intro`, `why_intro`, `contact`, `footer`, `projects_page`, `process_page`, `expertise_page`, `about_page`, `clients_page`

### List sections (many rows, ordered by `sort_order`)
`partners`, `features`, `expertise_items`, `projects`, `process_steps`, `material_partners`, `why_cards`, `process_principles`, `expertise_compare`, `about_timeline`, `about_leadership`, `about_certifications`, `clients`, `client_projects`

### Notable per-section field shapes
- **`hero`**: background image, 2-line headline (2nd line is the animated/italic accent), subtitle, primary/secondary CTA label+link, trust line, 3 stat blocks (value/suffix/label), partners-strip label.
- **`features`**: tag, title, description, `visual_kind` (`wind` | `bim` | `gauge` | `portal` | `energy` — controls which bespoke mini-visual renders), sort order.
- **`expertise_items`**: number label, title, **two description lengths** (`description` for the homepage tile, `short_description` for the expertise-page tab) plus a full `body` paragraph for the detail view, image, and 4 spec key/value pairs.
- **`projects`**: number label, name, location, system description, year, status (Delivered/In Progress), category tag (Commercial/Mixed-Use/Residential), scope, area, long description (used in the projects-page modal), cover image, sort order.
- **`manufacturing`**: 4 capability strings + 4 stat blocks, each stat having `value`, `decimals`, `suffix`, `label`.
- **`clients`**: name, **slug** (drives `/clients/:slug`), logo, hero image, tagline, short + long description, sector, city, established year, partner-since year, website, `featured` boolean (pins to top of `/clients`), sort order.
- **`client_projects`**: belongs to a `client_id` (FK, picked via a `select` field sourced from the `clients` table), plus full project detail — completion date, duration, KGS role, valuation, fee, gallery URLs, testimonial (quote/author/role), awards. This is the richest record in the schema and powers each client's detail page.
- Every sub-page (`projects_page`, `process_page`, `expertise_page`, `about_page`, `clients_page`) has its own singleton holding that page's hero copy (eyebrow/title/highlight/subtitle), section headings, and bottom CTA copy — independent from the homepage's copies of the same section.

### Admin sidebar grouping (`SIDEBAR_GROUPS`)
Mirrors the homepage section order, then sub-pages, then "Global — Footer." This is purely a UX grouping for editors and has no bearing on the public site.

## 7. Design system (`src/styles.css`)

Tailwind v4, **CSS-first** — theme tokens defined inline with `@theme inline { ... }`, no JS config file.

### Color tokens (light theme only — no dark mode is wired up despite the `dark:` variant existing)
- `--background`: pure white
- `--surface` / `--surface-2`: near-white / light grey (card backgrounds)
- `--ink` / `--ink-dim` / `--ink-mute`: near-black / mid-grey / light-grey text, in that order of emphasis
- `--line` / `--line-2`: hairline border greys
- `--brass` (`oklch(0.42 0.15 263)` ≈ `#014199`): **the single accent color**, used for links, CTAs, eyebrows, highlights — referred to as "brass" in code but is actually a **deep blue**
- `--brass-soft` / `--brass-glow`: tinted-blue surface / brighter accent variant

### Typography
- Display & body font: **Inter** (weights 300–700, including odd weights 450/550/650 for fine control)
- Mono font (used only for "eyebrow" labels and small meta text): **JetBrains Mono**
- Custom utilities: `.display-text` (hero-scale headings), `.display-section`, `.display-sub`, `.body-lead` (canonical paragraph style, 15px→17px responsive), `.eyebrow` (mono, brass-colored, tracked-out label)

### Signature motion/visual utilities (reusable — name these when requesting similar effects elsewhere)
- `.word-mask` / `.mask-line` — word-by-word or line-by-line reveal-on-load animation (`wordRise`/`maskRise` keyframes)
- `.shimmer-text` — animated gradient sweep through text (used for italic accent headline phrases)
- `.hero-breathe` — slow 22s scale/translate "breathing" loop on the hero background image
- `.hero-grid` / `.grid-bg` — faint animated drifting grid-line overlay
- `.dot-bg` — static dot-grid background with radial mask fade
- `.shine-on-hover` — diagonal light sweep across an element on hover (used on primary CTAs)
- `.tilt` — subtle lift-on-hover for cards
- `.pulse-ring` — expanding ring pulse (status/availability indicators)
- `.chip` / `.chip-dot` — pill-shaped tag with a glowing dot, brass-tinted
- `.btn-primary` / `.btn-ghost` — the two canonical button styles (filled brass-gradient pill vs. outlined ghost pill)
- `.nav-underline` — animated underline-on-hover/active for nav links
- `.marquee-track` — 38s linear infinite horizontal scroll (partner/material logo strips)
- `.container-kgs` — the site's content-width wrapper (max 1280px, responsive horizontal padding 1.5rem→3rem→4rem)

### Layout conventions
- Section padding, card radii (`--radius: 0.75rem` base), and spacing all flow from Tailwind v4 defaults plus the tokens above — there is no separate spacing scale override.
- Mobile-first; key breakpoints used throughout are `md:` (768px) and `lg:` (1024px)/`xl:` (1280px) for nav and grid changes.

## 8. Shared sub-page patterns

Every sub-page (`about`, `projects`, `process`, `expertise`, `clients`, `clients/:slug`) follows the same skeleton:

1. `Nav` (shared, always solid/light on sub-pages since there's no transparent hero to scroll over)
2. `PageHero` — breadcrumb, mono eyebrow, large title with one **highlighted/shimmer** phrase, subtitle, often a 3–4 stat strip
3. Page-specific content sections (timeline, tabs, comparison matrix, grids, modals, etc.) — each section typically has its own intro singleton (`*_eyebrow`/`*_heading`/`*_description`) plus a list table for repeated items
4. `PageCTA` — shared bottom CTA block ("title" + "copy", presumably linking to `/#contact`)
5. `Footer`

When asking for changes to "the same kind of section" across multiple pages, mention `PageHero`/`PageCTA` explicitly — they're shared components, so a tweak there is global.

## 9. Backend (Supabase)

- `src/integrations/supabase/client.ts` — Supabase client init (uses env vars from `.env`; **do not paste `.env` contents into prompts**).
- `supabase/config.toml` + `supabase/migrations/*.sql` — 11 migrations (dated 2026‑06‑09 through 2026‑06‑24) building out: all CMS tables listed in §6, a `user_roles` table (admin gating, checked in `admin/route.tsx`), and an enquiries/leads table feeding `/admin/enquiries`.
- Auth: Supabase email/password session; `/admin` checks `auth.getSession()` then verifies an `admin` row in `user_roles` for that user — otherwise shows "Not authorized."
- Images: either Supabase Storage (signed URLs admins upload), arbitrary external `http(s)` URLs, or legacy bundled assets under `/src/assets/...` resolved by `asset-map.ts`. The 9 bundled images in `src/assets/` are the current fallback/seed imagery (hero, manufacturing, statement portrait, 6× project covers, plus 6× "expertise" images named `exp-acp`, `exp-curtain`, `exp-skylight`, `exp-spider`, `exp-structural`, `exp-window`).

## 10. Things to know before requesting changes

- **Copy/data changes**: prefer editing via `/admin` if the field already exists in `cms-schemas.ts` — don't ask for a code change for something already CMS-editable. If a new field is needed, it requires a matching DB migration + a `cms-schemas.ts` entry + (sometimes) a component read of that field.
- **Fallback text lives in JSX**, not in the CMS — e.g. Hero's default headline `"Architectural facades, / engineered end to end."` is hardcoded in `Hero.tsx`. If the DB is empty, this is what visitors see. Decide explicitly whether a content request should change the **fallback** (code), the **seed data** (SQL/CMS), or both.
- **No dark mode** is actually wired despite Tailwind dark-variant scaffolding existing — don't assume toggling dark mode does anything visible.
- **Brass = blue** — the accent color variable is named `brass` for historical reasons but renders as deep blue (`#014199`-ish). Don't be confused by the name when asking for color tweaks; say "the accent blue" or reference the hex.
- **SSR + lazy loading**: homepage sections below the Hero are `React.lazy`-split. If adding a new homepage section, follow the same `lazy(() => import(...).then(m => ({ default: m.X })))` + `<Suspense fallback={<SectionSkeleton />}>` pattern to preserve load performance.
- **Routing is file-based**; new pages need a new file in `src/routes/`, and `routeTree.gen.ts` regenerates automatically on `bun run dev`/`build` — never hand-edit that generated file.
- **`PremiumLayer`** is a global, always-mounted decorative layer (cursor/scroll effects) — if a visual glitch appears site-wide (not page-specific), check there first.
- The site was scaffolded/is hosted through **Lovable** — some boilerplate meta (`"Lovable App"` title/og-tags in `__root.tsx`, `lovable-error-reporting.ts`) reflects that origin and may be worth a final pass to ensure the production title/OG tags are KGS-branded everywhere (currently `index.tsx` overrides title for `/`, but `__root.tsx`'s defaults still say "Lovable App" — worth checking for any sub-page that doesn't override head meta).
